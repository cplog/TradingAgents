1. End-to-end pipeline

Reports are markdown strings produced by LLM agents, stored in LangGraph state, serialized through the API, rendered in React, and optionally exported as self-contained HTML.

LangGraph agents (analysts → researchers → trader → PM) │ structured output → render_*() → markdown per section ▼ api/reports.py build_reports_dict() + analyst_coverage diagnostics │ JobResultPayload.reports: Record<sectionKey, markdown> ▼ Frontend ingestion ├─ reportMarkdown.ts sanitize, order, dedupe ├─ ReportSections.tsx ReactMarkdown + remarkGfm ├─ DecisionBrief.tsx derived summary (not raw PM paste) └─ useReportExport.ts DOM scrape → buildStandaloneReportHtml() │ ├─ reportExportBlocks.ts pure HTML fragments (brief, dims, provenance) └─ reportExport.ts EMBEDDED_CSS (~700 lines) + print rules

4. Markdown processing quirks

reportMarkdown.ts runs before every GFM render. Important behaviors:

  • Unicode space normalization — NBSP / thin spaces from LLMs collapsed for stable GFM
  • Strip leading FINAL TRANSACTION PROPOSAL — removed from analyst sections (kept on trader/PM)
  • Internal field stripping — _Internal report field: lines removed
  • Kronos placeholders — empty/skipped sections get muted .report-section--placeholder
  • News dedupe — consecutive duplicate blocks ≥180 chars collapsed
  • Section DOM ids — report-section-{key} for TOC anchors and export nav

Gap Raw markdown download bypasses sanitize pipeline — exported API markdown may include stubs and duplicate blocks that the UI hides.

7. Recommendations

Quick wins

  1. Align export tokens — Replace EMBEDDED_CSS palette with warm paper values from :root in index.css (phosphor, sage, stone-border, paper surface).
  2. Sanitize markdown download — Run sanitizeReportSectionBody server-side or in the download handler so raw == UI.
  3. Clarify PNG scope — Rename button to "PNG (summary card)" or expand capture target.

Medium term

  1. Markdown-first export — Build HTML from sanitized markdown + structured JSON (not DOM scrape). Keeps export stable when React changes.
  2. Shared brief component — Single source for DecisionBrief markup (React renders export preview; or shared template literals module).
  3. Report reading UX — Sticky desk playbook (rating + levels + invalidation), analyst sections collapsed by default with coverage badges, evidence callout cards for tables/quotes.

Structural

  1. Report schema version — Tag exports with schema version when section keys or brief fields change.
  2. Design token package — Extract CSS custom properties to frontend/src/theme/tokens.css imported by app and inlined in export.
